# 一键安装与构建脚本容错设计

## 背景

当前 macOS `一键安装依赖.command` 使用 `set -e`，Windows `一键安装依赖.bat` 在依赖安装或测试失败后主动退出。两者都会导致后续 `npm run build` 不执行，使用户无法获得一次完整运行中的构建结果。

## 目标

- macOS 与 Windows 脚本行为保持一致。
- 依赖安装或自动化测试失败后，仍然尝试执行构建。
- 每个阶段保留原始命令输出，便于从 npm 日志识别失败依赖或具体错误。
- 脚本结束时统一汇总安装、测试、构建三个阶段的结果。
- 任一阶段失败时，脚本最终返回非零退出码，避免自动化环境误判成功。

## 非目标

- 不自动修改 `package-lock.json`。
- 不自动重试、切换 npm 源或修复失败依赖。
- 不通过不可靠的正则表达式猜测具体失败包名。
- 不改变 `npm test` 或 `npm run build` 自身的行为。

## 设计

### 阶段执行

脚本依次运行：

1. 环境检查。
2. `npm ci`；无锁文件时运行 `npm install`。
3. `npm test`。
4. `npm run build`。
5. 输出阶段结果汇总。

Node.js 或 npm 不存在、Node.js 版本不满足要求时仍立即退出，因为这些情况无法启动任何 npm 阶段。

依赖安装、测试和构建阶段分别记录退出码，不因前一阶段失败而跳过后续阶段。即使依赖安装不完整，构建阶段也会实际执行，并保留其真实错误输出。

### 结果提示

每个失败阶段在命令结束后立即输出清晰提示：

- 依赖安装失败：提示查看上方 npm 日志，其中通常包含失败依赖名称。
- 测试失败：提示构建仍会继续。
- 构建失败：提示查看上方构建日志。

最终汇总逐项显示“成功”或“失败”。只有三个阶段都成功时显示 `dist/` 加载说明；否则说明流程已全部尝试，但存在失败，并返回退出码 1。

### 平台实现

- macOS：不使用全局 `set -e` 中止阶段；通过条件语句记录每条命令结果，同时保留 `set -u` 与 `pipefail`。
- Windows：移除安装和测试后的提前 `exit /b 1`，使用独立状态变量记录 `%errorlevel%`，最后统一决定退出码。

## 测试

增加静态脚本回归测试，验证：

- 两个平台脚本都在安装、测试失败路径后保留构建步骤。
- 两个平台脚本都记录三个阶段状态并统一汇总。
- 任一阶段失败时最终返回非零退出码。
- 环境检查失败仍立即退出。

另外实际运行 macOS 脚本涉及重新安装依赖，验证时以脚本回归测试、完整 `npm test`、`npm run build` 和 shell 语法检查为主。
