# 专业技能编辑与信息浮窗展示设计

## 背景

`UserProfile.skills` 已保存专业技能数据，设置页目前使用一个多行文本框编辑，但信息浮窗没有渲染该字段。用户无法从信息浮窗查看或点击专业技能，也无法像管理其他栏目一样对单项技能进行新增、排序和删除。

## 目标

- 在信息浮窗中展示“专业技能”，位置在“项目经历”之后、“奖项 / 荣誉”之前。
- 每项技能可单独点击并写入当前网页字段。
- 设置页专业技能改为紧凑行式编辑。
- 每项技能支持编辑、上移、下移、删除。
- 提供“添加专业技能”操作。
- 删除“每行一条，填充技能类字段时会合并为一段文本。”提示。
- 保持现有 `skills: string[]` 数据模型及自动填充合并行为不变。

## 非目标

- 不修改技能的数据结构。
- 不新增技能分类、熟练度或标签。
- 不修改简历解析和自动填充算法。
- 不顺带增加证书等其他信息浮窗栏目。

## 设置页设计

专业技能继续位于“实习与项目”页面末尾。原多行文本框替换为技能行列表：

```text
[技能内容输入框] [上移] [下移] [删除]
```

交互规则：

- 输入框直接修改对应数组项。
- “上移”与前一项交换位置；第一项禁用。
- “下移”与后一项交换位置；最后一项禁用。
- “删除”移除当前项。
- “添加专业技能”在列表末尾追加空字符串，并聚焦新输入框（若现有组件模式不支持稳定聚焦，则至少保证输入框立即出现）。
- 所有更新通过创建新数组完成，不原地修改 props。
- 空字符串可以在编辑过程中暂存，保存时沿用现有资料保存规则；不新增必填校验。

视觉上沿用现有项目中的按钮、输入框和排序操作样式，不引入卡片容器。

## 信息浮窗设计

在 `ProfileSections` 中按以下顺序渲染：

1. 基本信息
2. 教育经历
3. 实习经历
4. 项目经历
5. 专业技能
6. 奖项 / 荣誉
7. 自定义信息

专业技能分区规则：

- `profile.skills` 非空时显示分区。
- 每项技能渲染为单独的可点击字段。
- 点击时调用现有 `onFieldClick(value, key)` 写入网页字段。
- 每条技能使用稳定且唯一的工作键，例如 `skill-${index}`。
- 空字符串不渲染，避免出现空按钮。
- skills 为空或仅包含空字符串时不显示整个分区，与奖项等可选分区保持一致。

## 数据与兼容性

数据模型保持：

```ts
skills: string[]
```

因此：

- 旧资料无需迁移。
- JSON 备份和 WebDAV 同步格式无需变更。
- 简历解析输出无需变更。
- 自动填充技能类字段时仍使用现有合并文本逻辑。

## 测试策略

### 设置页

新增组件行为测试，覆盖：

- 点击“添加专业技能”追加空白项。
- 编辑单项只更新目标索引。
- 上移、下移保持正确顺序。
- 第一项上移和最后一项下移不可用。
- 删除只移除目标项。
- 页面不再包含旧提示文案和多行技能 textarea。

### 信息浮窗

扩展 `ProfileSections` 测试，覆盖：

- “专业技能”位于“项目经历”之后、“奖项 / 荣誉”之前。
- 多项技能分别显示。
- 点击技能传递正确值和工作键。
- 空字符串被过滤。
- 无有效技能时不显示分区。

### 最终验证

- 运行专业技能和信息浮窗聚焦测试。
- 运行完整 `npm test`。
- 运行 `npm run build`。
- 运行相关 lint 与 `git diff --check`。

## 验收标准

- 用户可以在设置页逐项新增、编辑、排序和删除专业技能。
- 旧提示文案已删除。
- 信息浮窗在奖项之前显示所有有效技能。
- 每项技能可以单独点击填入网页字段。
- 既有资料、备份、WebDAV 同步和自动填充行为不受影响。
